# 00 · 产品目标与非目标

> 状态：设计中。2026-09-15 建立；当前实现证据见[能力状态](./02-能力状态.md)。

## 一句话目标

sonic 是能理解目标、选择合适方法、在授权范围内做事、用证据交代结果的通用 AI 助手。“聪明”不只是回答流畅；“强大”不只是工具多；“可信”意味着做错、没做完或无法核实时都说清楚。

## 从用户任务看设计

用户说：“帮我找出这个仓库里的金额计算错误；只能动 `src/pricing.py`，不能联网；修完跑测试。”sonic 不能只把任务丢给模型。它需要保存原始约束、选定允许的工具、记录每次观察、在写入前校验工作区和授权，最后核对 diff 与测试。模型说“修好了”只能触发验收。

将来用户也可能要求“读三份公开资料，给我带出处的比较”。这类任务不需要仓库工作区，但仍需要状态、来源、预算和完成条件。因此 RepoFix 的阶段只能放在任务配置里，通用运行内核不能依赖 `pricing.py`、补丁或测试命令。

## 第一场景与最终目标

第一垂直场景推荐受限仓库问题助手：只读定位 → 经授权的隔离工作区修改 → 测试和 diff 核验 → 交付证据。第二场景是只读资料研究与回答，用同一内核证明抽象可复用。只有这两种任务都可重复验收，才逐步扩展多入口、长期记忆、跨应用操作和用户授权的主动协助。

当前仓库的 29 项教学测试不等于第一场景可用；真实模型、工作区隔离、完整路径权限、外部效果对账和 RepoFix Verifier 尚未交付。

## 明确不做

- 首版不搭建任意插件树、多 Agent 自治网络或默认接入全部 MCP 工具。新增抽象必须由第二个真实任务或评测失败证明需求。
- 不凭模型自述、漂亮 Demo 或单个测试宣称真实任务成功率。不虚构线上流量、Canary 或“提升 X%”。
- 不默认保存个人记忆，不替用户主动对外发消息、发布代码、消费资金或更改数据。任何主动行为需要单独授权范围和撤销办法。
- 不让任务配置提升用户授权或绕过策略；配置只能进一步收紧可用能力。

## 判断是否向目标靠近

观察任务完成率之外，还要记录未授权写入、错误完成判断、重复副作用、恢复后不确定状态、成本/时延和读者能否复现证据。安全违规与错误完成是发布阻断项，不用总体成功率掩盖。
