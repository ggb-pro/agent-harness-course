# ADR-0001：通用内核与垂直场景

状态：已接受（架构约束）；2026-09-15。

## 背景

sonic 的终点是通用助手，但现在只有课程 Harness 原型。一次实现“全部助手能力”会增加无法验收的接口；只做 RepoFix 且把其阶段写进 Runner，则以后每个非代码任务都要改内核。

## 决定

先用受限仓库问题助手证明真实场景，Core 保留任务无关的状态、事件、预算、执行治理和终态。定位、补丁、测试阶段归 RepoFix Profile；完成条件归其 Verifier。第二个只读资料研究 Profile 作为通用性检验。写操作需授权、隔离和持久化效果对账，不能以课程原型的示例策略代替。

## 未选方案

- 先建完整插件/多 Agent 平台：没有两个实际任务或评测结果证明其成本值得。
- 让模型自由决定所有阶段与权限：无法可靠验收、授权或恢复。
- 在 Runner 写死 RepoFix：初期简单，后续非代码任务会污染核心。

## 影响与复审

当前平铺教学模块先按边界归入 `core/models/capabilities`；`safety/memory/interfaces` 在实际能力落地时创建，不保留空占位。阶段 2 若无法共享核心，复审 Profile 契约；阶段 1 的诊断成功率不足时，不开放写操作。
