# sonic 设计阅读顺序

`sonic` 的长期目标是通用助手，不是把教学 RepoFix 原型换一个名字。[产品目标与非目标](./00-产品目标与非目标.md)回答“为什么做”；[架构与数据流](./01-架构与数据流.md)回答“任务怎样通过每一道门”；[能力状态](./02-能力状态.md)回答“现在实际上做到了什么”；[安全与隐私](./03-安全与隐私.md)和[演进路线](./04-演进路线.md)回答“何时可以安全扩展”。

有争议且会影响多处实现的决定写进 [ADR](./ADR/README.md)。设计中的示意接口与流程不等于代码已有功能；检验现状时以[代码、测试](../../代码/sonic/README.md)和能力状态表为准。

本文档继承了旧 TraceForge 课程设计的事件、权限、副作用和完成验证思路，但产品目标改为 sonic 通用助手，并将面试问题移至[独立题库](../../面经/题库/Agent-Harness-48题.md)。旧项目名保留在 Git 历史，不作为新文档的第二份正文。
